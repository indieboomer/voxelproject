# Hotbar and inventory

The nine-slot hotbar is centered at the bottom of the screen. Press **1-9** to select a slot, or use the **mouse wheel** to cycle assigned slots (including depleted assignments). **E** opens/closes Resources / Inventory and releases the cursor. While typing in search, E types normally; Escape closes the inventory. Click any hotbar slot while inventory is open, then choose **Assign to slot N** or **Clear active slot / empty hand**. Owned only is enabled by default; search matches names and semantic/display categories.

Left click uses the active entry. Resources place their block, axes and pickaxes mine, swords perform a short melee attack, and empty slots gather explicitly pickable plants. Right click also places an active resource; gear has no placement action. **F** retains the World API interaction event previously on E. C opens crafting; F10 opens settings.

New inventories receive a starter axe, pickaxe and sword in slots 1-3. Slot 4 is empty for hand gathering. Bow equipment is currently unavailable; loading an older world removes its bow counts and clears bow assignments for host and guest accounts. There is no durability system yet. Swords damage creatures, not other players. Tool crafting is not added in this revision.

All resources define `harvest_category` in `data/resources.json`, emitted by `tools/build_resources.py` into the resource catalog. Axes affect wood and plants; pickaxes affect stone, ore, and soil. Grass-covered soil belongs to soil. An explicit `hand_pickable` flag enables single-click empty-hand gathering for pumpkin, short grass, reeds, flax, wild herbs, fern, clover, lavender, red poppy, bluebell, cattail, brown mushroom, glowcap, thorn bush and dry shrub. Leaves and harder materials still require tools. Depleted resource slots are not empty hands. Incompatible tools, swords, bows, and resource stacks never perform ordinary mining. The existing block hardness determines the number of tool uses required.

Hotbar entries reference inventory types; they do not hold separate stacks. Depleted entries remain assigned and reactivate when inventory increases. Mining, crafting, placement and World API grants/removals update the same account balances. Clearing a slot never removes inventory. The optional block-target outlines use tool compatibility and the same placement validation as interactions.

`Account` saves gear counts, nine assignments, selected slot and equipment revision alongside authoritative resource balances. Host state and guest accounts survive world saves. Guests reconnect using the existing identity (Steam ID, or Direct/LAN nickname); Direct players should keep their nickname. Preferences and theme remain device-local. Network protocol is now 8, so all players need the updated executable.

Guests send `ItemAction` intents containing aim, target, hotbar revision and active item. The host rechecks assignment ownership, item identity, raycast/line of sight, range, tool categories, block hardness, placement bounds/support, inventory and player collision before modifying blocks or balances. Host-local actions use the same validator. Clients no longer send authoritative block edits. Absolute inventory revisions prevent stale balances; equipment revisions tolerate the equipment packet arriving after its corresponding action and reject stale actions after a later selection. Reliable message IDs suppress duplicate requests. Held item references are broadcast in authoritative snapshots.

Validation: equipment tests cover semantic categories, forbidden mining, hit counting, exact placement cost, collision/range/obstruction failures, empty-slot cycling, depleted references, serialized intents, save/reconnect records, stale equipment and weapon line of sight. Offscreen UI previews use the actual hotbar renderer (`target/ui-fantasy-hotbar.png`).

The E inventory panel sits above the hotbar, keeping assignments visible and clickable. Use **Full resource list** to browse unowned resources, or **Owned only** for your inventory. The original held-item pose and use motion are rotated together 90 degrees counterclockwise around the vertical grip axis (viewed from above). Inventory icons and remote models retain their original orientation.

The axe additionally twists 1270 degrees around its local handle axis (equivalent to 190 degrees, including the additional 90-degree counterclockwise adjustment), before the shared held animation transform.

Multiplayer held tools and resources now follow the animated right-hand grip, including work and attack poses. Empty/depleted selections show no held mesh. See [PLAYER_ANIMATIONS.md](PLAYER_ANIMATIONS.md) for gestures, action animations, and protocol compatibility.
