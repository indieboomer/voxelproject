# World API (v1.2.0)

> Generated by `tools/gen_world_api.py` from `world_api/schema.yaml` -- do not edit by hand.

The Lua API exposed to sandboxed rule modules as the `api` table passed into on_tick/on_cast/on_death/on_block_break. Every member is flat under `api` (single "world" namespace) -- there is no api.player.*/api.world.* nesting yet. `namespace: world` is still tagged on each entry so a future namespace can be introduced without reshaping this schema or its generated artifacts.

## Sandbox / engine

- Runtime: Lua 5.4 via mlua
- Tick interval: 0.1s (~10/sec)
- Allowed stdlib: table, string, math
- Removed stdlib: os, io, require, debug, package (never exist in this sandbox)
- Memory limit: 8,388,608 bytes
- Time budget: 5ms per call (checked every 1000 instructions)

Each module gets its own Lua VM: one module's globals/persistent state can never leak into another's, and a crashed module cannot corrupt the rest. A module that exceeds its time/instruction/memory budget, or throws any runtime error (including from a call this schema documents as budget-limited, once every call in the same tick has already consumed its own separate budget), is automatically disabled; the host is notified with the error so a rule going silently dark is never mistaken for "nothing happened".

## Multiplayer authority

Every World API call executes ONLY on the host -- Lua does not run on joined clients at all (ScriptHost is host-only state). A module's effects (block edits, creature spawns/state, weather, time of day, broadcasts, item grants, player attributes) reach clients purely through the replication channels below; there is no separate "multiplayer mode" a rule opts into. Only the host can generate, activate, or run a module (a menu/UI restriction, not something this API itself enforces or exposes) -- so an on_cast's `event.player_id` is currently always the host's own id, even though the API shape allows for any player.

Replication channel per kind of effect:

- **block_edits**: Reliable, ordered, resent until acknowledged (ReliableMsg::BlockEdit) -- guaranteed delivery, may lag under packet loss.
- **creature_state**: Best-effort, ~20 Hz (UnreliableMsg::Snapshot) -- a dropped snapshot is superseded by the next; no guaranteed delivery, but self-healing within one snapshot interval.
- **weather_and_time_of_day**: Carried in the same best-effort Snapshot as creature state -- see creature_state.
- **broadcast_messages**: One reliable Notify message per api.broadcast call, the same path used for host system notifications (rule enabled/disabled, player joined, etc.).
- **item_grants**: One reliable, targeted ReliableMsg::GrantItem per give_item call, sent only to the named player_id (not broadcast to everyone like Notify) -- the host applies its own grant locally instead of round-tripping through the network.
- **player_attributes**: health, poisoned, speed_multiplier, and jump_multiplier all ride the same best-effort Snapshot creature_state already uses (~20Hz, self-healing) -- broadcast to every connected player, not just the one they belong to, the same way carrying_crystal already is. A player's own client also applies its own speed_multiplier/jump_multiplier from this to its local movement physics, since movement itself is simulated client-side.

## Persistence

- Saved fields: name, prompt, source, enabled
- Save format: bincode, inside WorldSave.modules (see save.rs) -- ModuleSaveEntry's field set is part of the save file's binary layout, so it cannot gain/lose/reorder fields without breaking old saves; see the changelog for how to evolve it safely.

A module's Lua runtime state (persistent global tables/variables used to remember things between calls, e.g. a "previous tick" table keyed by player id) is NOT saved. Reloading a world re-executes `source` from scratch in a fresh Lua VM, so any such memory resets to its initial value -- only a module's enabled/disabled flag and source code survive a save/reload, never its accumulated runtime state.

Every module's `source` may begin with a `-- api_version: X.Y.Z` comment line recording which World API version it was written/generated against. Rules generated by the LLM pipeline always get this tag added automatically; hand-written starter rules under modules/ carry it too. It is informational only (never enforced/validated against the running engine's version) so that older untagged rules keep loading exactly as before -- see CHANGELOG.md.

## Budgets and limits

### `block_edits_per_call` = 32
- Scope: per module, per on_tick/on_death/on_block_break call
- Applies to: `replace_block`
- On exhausted: replace_block returns false; not an error.

### `creature_spawns_per_call` = 4
- Scope: per module, per call
- Applies to: `spawn_creature`, `spawn_creature_near_player`
- On exhausted: the call returns nil; not an error.

### `find_radius_max` = 10.0
- Scope: global
- Applies to: `find_creatures`, `find_blocks`, `spawn_creature_near_player`
- Note: find_creatures/find_blocks clamp their radius argument into [0, 10]; spawn_creature_near_player clamps into [1, 10] (its floor is 1, not 0). nearest_creature/nearest_player take no radius at all -- they search every creature/player unconditionally and return the closest.

### `find_results_max` = 64
- Scope: global
- Applies to: `find_creatures`, `find_blocks`
- On exceeded: results beyond the cap are silently dropped, not an error; don't rely on finding more than this.

### `block_edits_per_cast_call` = 300
- Scope: per instant-spell module, per on_cast call -- higher than block_edits_per_call since a spell runs once, not ~10/sec
- Applies to: `replace_block`
- On exhausted: replace_block returns false; not an error.

### `creature_spawns_per_cast_call` = 30
- Scope: per instant-spell module, per on_cast call -- higher than creature_spawns_per_call since a spell runs once, not ~10/sec
- Applies to: `spawn_creature`, `spawn_creature_near_player`
- On exhausted: the call returns nil; not an error.

### `item_grant_max` = 500
- Scope: per give_item call -- caps the amount argument itself, not a call count
- Applies to: `give_item`
- On exceeded: amount is silently clamped to this value, not an error.

### `attribute_multiplier_min` = 0.1
- Scope: global
- Applies to: `set_player_speed`, `set_player_jump`
- Note: A multiplier below this (e.g. 0) would functionally freeze/disable the attribute; clamped instead of allowed.

### `attribute_multiplier_max` = 5.0
- Scope: global
- Applies to: `set_player_speed`, `set_player_jump`
- On exceeded: multiplier is silently clamped into [attribute_multiplier_min, attribute_multiplier_max], not an error.

### `max_health` = 100.0
- Scope: every player, fixed -- not per-kind like a creature's max_health
- Applies to: `heal_player`
- Note: Also the starting health for every player, every session (see persistence.player_state_not_saved).

### `poison_tick_secs` = 10.0
- Scope: global -- how often every currently-poisoned player loses health, engine-driven, not a Lua call
- Applies to: `set_poisoned`
- Note: 1 health lost per tick, for as long as PlayerSnapshot.poisoned stays true. No Lua callback fires for this -- it's pure engine state, only observable by polling api.players()/nearest_player().health from on_tick.

## Types

### `PlayerSnapshot`
One connected player's state, as returned by players()/nearest_player().

  - `id` (integer) -- Stable per-connection player id; 0 is always the host.
  - `x` (number)
  - `y` (number)
  - `z` (number)
  - `carrying_crystal` (boolean) -- True once this player has ever broken a Crystal block this session. One-shot: never resets to false from this API (there is no 'drop crystal' action).
  - `speed` (number) -- Horizontal speed in blocks/sec -- excludes vertical (fall/jump) motion.
  - `vertical_speed` (number) -- Signed vertical speed: positive while rising (e.g. jumping), negative while falling.
  - `on_ground` (boolean) -- True when standing on solid ground. Never true the same tick vertical_speed is positive -- a jump sets both at once, so 'on_ground and vertical_speed > 0' can never be true. There is no separate on_jump/on_land event; detect a one-shot transition by remembering the previous tick's on_ground per player id.
  - `running` (boolean) -- True while sprinting, as opposed to walking.
  - `in_water` (boolean) -- True while standing in a water block.
  - `health` (number) -- 0-100. Starts at 100 for every player every session -- like resources, health is NOT saved/reloaded with the world (see persistence.player_state_not_saved).
  - `poisoned` (boolean) -- While true, this player loses 1 health every poison_tick_secs, until something sets it back to false (e.g. a future medication item -- see set_poisoned). Sourced from and reported through this flag only; there is no separate 'poison timer' exposed.
  - `speed_multiplier` (number) -- Multiplies this player's base walk/sprint speed. 1.0 = normal; see set_player_speed.
  - `jump_multiplier` (number) -- Multiplies this player's base jump speed (so roughly jump *height* scales with its square, not linearly). 1.0 = normal; see set_player_jump.

### `PlayerSnapshotWithDistance`
PlayerSnapshot plus the straight-line distance from the query point, as returned by nearest_player().

  - `id` (integer) -- Stable per-connection player id; 0 is always the host.
  - `x` (number)
  - `y` (number)
  - `z` (number)
  - `carrying_crystal` (boolean) -- True once this player has ever broken a Crystal block this session. One-shot: never resets to false from this API (there is no 'drop crystal' action).
  - `speed` (number) -- Horizontal speed in blocks/sec -- excludes vertical (fall/jump) motion.
  - `vertical_speed` (number) -- Signed vertical speed: positive while rising (e.g. jumping), negative while falling.
  - `on_ground` (boolean) -- True when standing on solid ground. Never true the same tick vertical_speed is positive -- a jump sets both at once, so 'on_ground and vertical_speed > 0' can never be true. There is no separate on_jump/on_land event; detect a one-shot transition by remembering the previous tick's on_ground per player id.
  - `running` (boolean) -- True while sprinting, as opposed to walking.
  - `in_water` (boolean) -- True while standing in a water block.
  - `health` (number) -- 0-100. Starts at 100 for every player every session -- like resources, health is NOT saved/reloaded with the world (see persistence.player_state_not_saved).
  - `poisoned` (boolean) -- While true, this player loses 1 health every poison_tick_secs, until something sets it back to false (e.g. a future medication item -- see set_poisoned). Sourced from and reported through this flag only; there is no separate 'poison timer' exposed.
  - `speed_multiplier` (number) -- Multiplies this player's base walk/sprint speed. 1.0 = normal; see set_player_speed.
  - `jump_multiplier` (number) -- Multiplies this player's base jump speed (so roughly jump *height* scales with its square, not linearly). 1.0 = normal; see set_player_jump.
  - `distance` (number)

### `CreatureSnapshot`
One creature's state, as returned by creatures()/find_creatures().

  - `id` (integer) -- Stable creature id, valid until it despawns (destroy/damage-to-zero).
  - `kind` (string)
  - `x` (number)
  - `y` (number)
  - `z` (number)
  - `health` (number)
  - `max_health` (number) -- Fixed per kind (sheep 12, chicken 6); never changes at runtime.

### `CreatureSnapshotWithDistance`
CreatureSnapshot plus distance from the query point, as returned by nearest_creature().

  - `id` (integer) -- Stable creature id, valid until it despawns (destroy/damage-to-zero).
  - `kind` (string)
  - `x` (number)
  - `y` (number)
  - `z` (number)
  - `health` (number)
  - `max_health` (number) -- Fixed per kind (sheep 12, chicken 6); never changes at runtime.
  - `distance` (number)

### `BlockPos`
One integer world position, as returned by find_blocks().

  - `x` (integer)
  - `y` (integer)
  - `z` (integer)

### `CastEvent`
Passed as `event` to on_cast.

  - `player_id` (integer) -- id of the player who clicked Run (matches PlayerSnapshot.id). Only the host can run a spell, so this is currently always the host's id, but treat it as any connected player's id -- don't hardcode 0.

### `DeathEvent`
Passed as `event` to on_death. The creature no longer exists by the time this fires.

  - `kind` (string)
  - `x` (number) -- Last position before death.
  - `y` (number)
  - `z` (number)

### `BlockBreakEvent`
Passed as `event` to on_block_break. Only real player-caused breaks (mining) fire this -- a rule's own replace_block calls never do, even ones that set a block to air.

  - `kind` (string) -- Snake_case id of the block that was broken -- see block_kinds. Same vocabulary as get_block's return value.
  - `x` (integer)
  - `y` (integer)
  - `z` (integer)
  - `player_id` (integer) -- id of the player who broke it (matches PlayerSnapshot.id).

## Query methods (`api.<name>(...)`)

### `api.players()`
Every connected player.

Returns: `PlayerSnapshot[]` -- Empty array if nobody is connected.

### `api.nearest_player(x, y, z)`
The single closest connected player to a point. Prefer this over looping players() yourself when you just need the closest one.

Parameters:
  - `x` (number)
  - `y` (number)
  - `z` (number)

Returns: `PlayerSnapshotWithDistance | nil` -- nil if no players are connected.

### `api.creatures()`
Every creature in the world.

Returns: `CreatureSnapshot[]` -- Empty array if none exist.

### `api.find_creatures(kind, cx, cy, cz, radius)`
Creatures of one kind within a radius of a point.

Parameters:
  - `kind` (string) -- "sheep", "chicken", or "any". An unrecognized string is treated the same as "any" -- it is NOT an error, so a typo silently matches every creature instead of failing loudly.
  - `cx` (number)
  - `cy` (number)
  - `cz` (number)
  - `radius` (number) -- Clamped into [0, find_radius_max].

Returns: `CreatureSnapshot[]` -- Up to find_results_max entries; excess matches are silently dropped.
Budget: see `find_radius_max` above.

### `api.nearest_creature(kind, x, y, z)`
The single closest creature of one kind to a point. No radius argument -- it searches every creature in the world unconditionally.

Parameters:
  - `kind` (string) -- "sheep", "chicken", or "any" -- same unrecognized-string-means-any behavior as find_creatures.
  - `x` (number)
  - `y` (number)
  - `z` (number)

Returns: `CreatureSnapshotWithDistance | nil` -- nil if no creature of that kind exists.

### `api.get_block(x, y, z)`
The block at an integer position.

Parameters:
  - `x` (integer)
  - `y` (integer)
  - `z` (integer)

Returns: `string` -- Snake_case block id -- see block_kinds. Positions outside the loaded/generated world, or above/below the vertical bounds, read as "air", never an error.

### `api.find_blocks(kind, cx, cy, cz, radius)`
Positions of every block of one kind within a radius of a point.

Parameters:
  - `kind` (string) -- A block id from block_kinds, OR the special category alias "wood" (matches any tree species: oak_wood, spruce_wood, birch_wood, cherry_wood). Unlike find_creatures' kind, an unrecognized string here returns an EMPTY result, not "match everything" -- this asymmetry is a real gotcha, not a design you can rely on being consistent across query methods.
  - `cx` (integer)
  - `cy` (integer)
  - `cz` (integer)
  - `radius` (number) -- Clamped into [0, find_radius_max].

Returns: `BlockPos[]` -- Up to find_results_max entries; excess matches are silently dropped.
Budget: see `find_radius_max` above.

### `api.terrain_height(x, z)`
The integer y of the topmost solid ground block at a column. Useful for placing/spawning things at the correct height instead of guessing.

Parameters:
  - `x` (integer)
  - `z` (integer)

Returns: `integer`

### `api.distance(x1, y1, z1, x2, y2, z2)`
Straight-line distance between two points. Prefer this over writing your own sqrt(dx*dx+dy*dy+dz*dz).

Parameters:
  - `x1` (number)
  - `y1` (number)
  - `z1` (number)
  - `x2` (number)
  - `y2` (number)
  - `z2` (number)

Returns: `number`

### `api.get_resource_count(player_id, kind)`
How much of one resource a player's inventory currently holds. Same host-only limitation as take_item -- a remote player's inventory isn't tracked host-side yet.

Parameters:
  - `player_id` (integer) -- Must be the host's own id or this returns nil.
  - `kind` (string) -- A block id from block_kinds.

Returns: `integer | nil` -- nil if player_id isn't the host or kind isn't a real gatherable resource -- indistinguishable from Lua. Otherwise the count, which can legitimately be 0 (holds none, as opposed to nil meaning 'can't tell').

## Action methods (`api.<name>(...)`)

### `api.chase(creature_id, x, y, z)`
Makes a creature move toward a point at increased speed. Call it again every tick to keep it chasing -- stop calling it and the creature reverts to normal wandering within about a third of a second (there is no separate "stop chasing" call).

Parameters:
  - `creature_id` (integer)
  - `x` (number)
  - `y` (number)
  - `z` (number)

Returns: `nil` -- Always nil, even if creature_id doesn't exist -- there is no way to tell from Lua whether the call actually found the creature.

### `api.damage(creature_id, amount)`
Reduces a creature's health. Fires on_death (to every module, not just the caller) if this brings health to zero or below, and despawns it.

Parameters:
  - `creature_id` (integer)
  - `amount` (number)

Returns: `nil` -- Always nil, whether or not creature_id exists.

### `api.destroy(creature_id)`
Removes a creature immediately regardless of remaining health, and fires on_death.

Parameters:
  - `creature_id` (integer)

Returns: `nil` -- Always nil, whether or not creature_id exists.

### `api.spawn_creature(kind, x, y, z)`
Spawns a new creature at a position.

Parameters:
  - `kind` (string) -- "sheep" or "chicken"; anything else (including a typo) silently becomes "sheep" -- not an error.
  - `x` (number)
  - `y` (number)
  - `z` (number)

Returns: `integer | nil` -- The new creature's id, or nil if this call's spawn budget is already used up.
Budget: see `creature_spawns_per_call` above.

### `api.spawn_creature_near_player(player_id, kind, radius)`
Spawns a new creature at a random point within radius blocks of a player (horizontally; height snaps to terrain). Prefer this over spawn_creature plus your own random offset when the rule is about spawning near a specific player.

Parameters:
  - `player_id` (integer)
  - `kind` (string) -- Same silent-default-to-sheep behavior as spawn_creature.
  - `radius` (number) -- Clamped into [1, find_radius_max] -- note the floor is 1, not 0, unlike the find_* methods.

Returns: `integer | nil` -- The new creature's id, or nil if player_id isn't connected OR the spawn budget is used up -- these two failure cases are indistinguishable from Lua.
Budget: see `creature_spawns_per_call` above.

### `api.give_item(player_id, kind, amount)`
Grants items straight into a player's Resources inventory (the panel populated by hand-gathering blocks), bypassing the world entirely. Only use this when the request explicitly asks to add to a player's inventory/resources -- for everything else ("add 100 stone", "fill this area with water"), prefer replace_block to place blocks in the world instead.

Parameters:
  - `player_id` (integer) -- Target player (matches PlayerSnapshot.id).
  - `kind` (string) -- A block id from block_kinds, but only the ones gatherable by hand (a resource, not e.g. "air" or "water") count -- anything else is rejected.
  - `amount` (integer) -- Clamped into [0, item_grant_max].

Returns: `boolean` -- false if kind isn't a grantable resource, player_id isn't connected, or amount clamped to 0 -- these failure cases are indistinguishable from Lua. true otherwise.
Budget: see `item_grant_max` above.

### `api.take_item(player_id, kind, amount)`
Removes items from a player's Resources inventory -- the reverse of give_item. ONLY works for the host's own player right now: a remote player's inventory isn't tracked host-side (nothing reports it up), so this is a no-op for any other player_id. Prefer give_item for a remote player (granting doesn't need to know what they already have).

Parameters:
  - `player_id` (integer) -- Must be the host's own id (see summary) or this always fails.
  - `kind` (string) -- A block id from block_kinds; only a gatherable resource can be held at all.
  - `amount` (integer) -- How many to remove.

Returns: `boolean` -- true only if player_id is the host AND it currently holds at least amount of kind (the whole amount is removed, never a partial take). false for every other case -- wrong player, unknown/ungrantable kind, or not enough held.

### `api.damage_player(player_id, amount)`
Reduces a player's health, clamped at 0 -- there is no death/respawn system yet, so health just stops there.

Parameters:
  - `player_id` (integer)
  - `amount` (number)

Returns: `boolean` -- false if player_id isn't connected, true otherwise.

### `api.heal_player(player_id, amount)`
Restores a player's health, clamped at 100 (max_health).

Parameters:
  - `player_id` (integer)
  - `amount` (number)

Returns: `boolean` -- false if player_id isn't connected, true otherwise.

### `api.set_poisoned(player_id, poisoned)`

Parameters:
  - `player_id` (integer)
  - `poisoned` (boolean)

Returns: `boolean` -- false if player_id isn't connected, true otherwise.

### `api.set_player_speed(player_id, multiplier)`
Sets a player's speed_multiplier (applied to their base walk/sprint speed).

Parameters:
  - `player_id` (integer)
  - `multiplier` (number) -- Clamped into [attribute_multiplier_min, attribute_multiplier_max].

Returns: `boolean` -- false if player_id isn't connected, true otherwise.
Budget: see `attribute_multiplier_max` above.

Sets a player's jump_multiplier (applied to their base jump speed).

Parameters:
  - `player_id` (integer)
  - `multiplier` (number) -- Clamped into [attribute_multiplier_min, attribute_multiplier_max].

## Events

### `function on_tick(api)`
- Required: yes
- Frequency: ~10/sec, every tick_interval_secs, for as long as the module is enabled
- Defines a RULE module. Required unless the module defines on_cast instead -- a module must define EXACTLY ONE of on_tick or on_cast, never both, never neither; Module::load rejects any other combination.

### `function on_cast(api, event)`
- Required: no
- Frequency: Exactly once, immediately, when the host clicks Run in the Rules panel -- never on a timer, never re-run automatically.
- `event` shape: `CastEvent` (see Types above)
- Defines an INSTANT SPELL module instead of a RULE: a one-time immediate action with no ongoing condition to check (e.g. "add 100 stone", "spawn a dozen chickens around me", "heal me"), as opposed to a RULE's continuous "when/if/at night/while ..." behavior. Mutually exclusive with on_tick -- see on_tick's desc. Since it only runs once per click instead of ~10/sec, its per-call action budgets are higher than a RULE's -- see block_edits_per_cast_call and creature_spawns_per_cast_call.

### `function on_death(api, event)`
- Required: no
- `event` shape: `DeathEvent` (see Types above)
- Fires once per creature death, from any cause (this module's or another enabled module's api.damage/api.destroy). Does NOT chain: if an on_death handler itself kills another creature, that second death does not fire on_death again within the same tick.

### `function on_block_break(api, event)`
- Required: no
- `event` shape: `BlockBreakEvent` (see Types above)
- Fires once per real player-caused block break (mining). A rule's own replace_block calls, even ones that set a block to air, never trigger this.
