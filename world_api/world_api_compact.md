World API v1.28.0 (the `api` table passed into on_tick/on_cast/on_death/on_block_break/on_interact)

Source is limited to 65,536 UTF-8 bytes. Initialization and every callback each receive 100,000 Lua instructions and a 5ms wall-time budget. Hooks check every 1,000 instructions; API entry/exit and execution completion also check time. Limits reset for each invocation. Budget exhaustion cannot be caught or suppressed with pcall/xpcall; ordinary Lua errors remain catchable. Native operations are not forcibly interrupted, so the time budget is a cooperative limit, not a hard realtime deadline. Each host tick/cast dispatch admits at most 16 callbacks under shared ceilings of 400,000 instructions, 4,096 API calls, 262,144 native work units and 20ms cooperative time. Admission reserves the full per-callback allowance (plus initialization for a failed VM reload); unstarted work waits for a later dispatch without resetting or replaying the callback. Nearby campfire placement charges (2*ceil(radius)+1)^2 * 72 units times (1 + staged block edits), plus the ordinary snapshot cost; radius is 2..8. Other environment queries/actions charge 200 units times (1 + staged block edits); find_campfires charges twice its bounding cube times (1 + staged block edits). Creature snapshots also account for staged-block lookups for in_water. Native work is limited to 65,536 units per callback: find_blocks charges its bounding cube candidates times (1 + staged block edits); other methods charge 1 + creature count + player count + staged player effects + staged block edits. find_blocks also checks time between scan rows. These units conservatively bound repeated scans, not CPU instructions or hard realtime.
Pending callbacks use round-robin recipient queues, FIFO within each rule. Tick requests coalesce to one pending tick per rule. Events retain their original recipient and payload, but query current world state when run. Disabling/deleting a rule cancels its queued work. Re-enabling a rule or adding a new rule never delivers old events to that new activation. Queues hold at most 512 callbacks total and 64 per module; newest excess requests are dropped with a visible saturation notice. Only the first 512 incoming block-break events and first 512 interactions per dispatch are considered. Queues are transient and are not saved on world exit. Up to 64 modules are loaded; saved overflow or invalid source is preserved without execution and reported to the host. Removing loaded modules and reloading the world can make room for preserved overflow modules.
World API spawns return nil at 256 live creatures (including starter creatures); destroying one frees capacity.
All API methods share 512 calls per callback; exceeding this aborts execution. Coordinates must be within +/-1000000 blocks; all numeric arguments must be finite f32 values.
Each callback is one transaction. Block edits, creature spawning/chasing/ damage/destruction, player effects, inventory changes, weather (including its RNG/timer), time, and broadcasts are staged. Queries read the callback's own accepted writes plus earlier successful callbacks in the same host dispatch. Returned query tables are snapshots; query again after an action. time_of_day/is_night/weather properties refresh after API calls. Movement and physics are not simulated during a callback; terrain_height remains the procedural generator height, not a scan of edited blocks. Failed callbacks emit no death events, broadcasts, replication effects, or spawn ID/RNG advances. Successful callbacks commit in scheduler order. Death events enqueue one level of notifications only after their cause commits. A failing death handler rolls back only its own changes, not the earlier death that triggered it. Ordinary errors caught by Lua do not abort the transaction; instruction/time/API/native-work/broadcast budget failures cannot be caught. This is callback failure rollback, not user-facing history/undo or atomic network delivery. Shared admission bounds callback work; native commit/apply and operating-system scheduling can overrun the cooperative wall-time target.

Queries:
- api.get_player_journal(player_id): Read a connected player's saved campkeeper contracts, recovery location, and twenty traveler quests (quests and quests_completed added in 1.28.0). Detached table; scripts cannot directly claim rewards or change built-in progress. Quest givers are peaceful patrol NPCs, separate from combat creatures. Returns PlayerJournal | nil. nil for a missing player.
- api.get_equipped_item(player_id): Read the selected resource/equipment ID, e.g. crystal or pickaxe. Returns nil for missing players, empty slots or depleted stacks; respects staged inventory changes. Holding a crystal illuminates nearby terrain within six blocks, including daytime caves. Unlike carrying_crystal, this reflects the current selection and inventory. Returns string | nil.
- api.get_player_inventory(player_id): Complete detached inventory: resources maps resource IDs to counts, items maps axe/pickaxe/sword/bow to counts, elements maps earth/fire/water/life/death to counts, and mana is an integer. Includes zeros, staged changes and earlier committed callbacks; nil for missing player. Returns table | nil.
- api.get_mana(player_id): Available mana, including staged changes. During an instant, the engine has already reserved its 5 mana cast fee; do not subtract that fee again. Returns integer | nil.
- api.get_element_count(player_id, element): Element count; names earth, fire, water, life, death are case insensitive. nil for missing player/unknown element. Returns integer | nil.
- api.get_item_count(player_id, kind): Count an equipment item (axe, pickaxe, sword, bow) or collectible resource ID. nil for unknown player/ID. Returns integer | nil.
- api.get_resource_elements(kind): Per-unit composition from the host crafting catalog, keyed by earth/fire/water/life/death including zeros. nil for non-resource ID; a zero composition cannot be decomposed. Returns table | nil.
- api.get_item_recipe(kind): For axe/pickaxe/sword/bow returns create and decompose tables. Each has resources={iron=count, oak_wood=count} and mana=cost. Create consumes listed materials; decompose returns them. nil for unknown equipment. Returns table | nil.
- api.get_devices(): List automation devices in deterministic cell order (at most 64 by default). Each snapshot has x/y/z, kind, enabled, mana, signal, activity, recipe, element, rotation, reserve, progress (0..1), items and output maps. Matter map keys are element:earth/fire/water/life/death, resource:<block_id>, item:axe/pickaxe/sword/bow or creature:<kind>. Returned tables are copies. Production runs separately on fixed host ticks; never call an LLM for production. Returns table[]. Device snapshots including staged changes.
- api.get_device(x, y, z): Inspect one automation device at any of its occupied cells; coordinates in the snapshot identify its base. Same fields as get_devices, plus eject_contents for chest/smelter mode, fuel_heat for smelter fuel uses, height in blocks, and powered_ticks for remaining paid lantern/altar/shrine runtime in 100ms ticks. All occupied cells report automation_device through get_block and cannot be overwritten with replace_block; use player packing controls to preserve contents. Returns table | nil. Device snapshot, or nil for an empty cell.
- api.get_campfire(x, y, z): Inspect a campfire block, including burning and night-light state. Returns CampfireSnapshot | nil. nil unless this block is a campfire.
- api.find_campfires(x, y, z, radius): Find nearby campfire snapshots; respects callback scan budgets. Prefer small radii and avoid nested scans. radius: Clamped to 0..12. Returns CampfireSnapshot[]. At most find_results_max entries in scan order, not nearest order.
- api.get_water(x, y, z): Inspect water depth, surface elevation, and the visual river/stream current. No fluid simulation or writable flow override. Returns WaterSnapshot | nil. nil unless the queried block is water. Reads staged edits.
- api.get_waterfalls(x, y, z): Inspect spills at a source water block. Requires open sky, an adjacent open drop, loaded neighbors, and lower receiving water. Use get_water().surface_y-1 to query its top block. Returns WaterfallSnapshot[]. Zero to four directional spills. Changing source, receiving water, or obstructions through replace_block changes the effect; reads staged edits.
- api.can_spawn_fish(x, y, z): Check a submerged fish body and full 7x7 water layer centered at floor(x,y,z). Reads staged edits. Returns boolean.
- api.players(): Every connected player. Returns PlayerSnapshot[]. Empty array if nobody is connected.
- api.nearest_player(x, y, z): The single closest connected player to THREE numeric coordinates (x, y, z), not a player ID or position table. To find the caster, match event.player_id in api.players(); for a nearby campfire use place_campfire_near_player(event.player_id, 6). Returns PlayerSnapshotWithDistance | nil. nil if no players are connected.
- api.creatures(): Every creature in the world. Returns CreatureSnapshot[]. Empty array if none exist.
- api.find_creatures(kind, cx, cy, cz, radius): Creatures of one kind within a radius of a point. kind: "sheep", "chicken", "stone_golem", "wolf", "stinger", "cow", "goblin", "sunscorch", "zombie", "skeleton", "dragon_green", "dragon_red", "fish", or "any". An unrecognized string is treated the same as "any" -- it is NOT an error, so a typo silently matches every creature instead of failing loudly. radius: Clamped into [0, find_radius_max]. Returns CreatureSnapshot[]. Up to find_results_max entries; excess matches are silently dropped.
- api.nearest_creature(kind, x, y, z): The single closest creature of one kind to a point. No radius argument -- it searches every creature in the world unconditionally. kind: "sheep", "chicken", "stone_golem", "wolf", "stinger", "cow", "goblin", "sunscorch", "zombie", "skeleton", "dragon_green", "dragon_red", "fish", or "any" -- same unrecognized-string-means-any behavior as find_creatures. Returns CreatureSnapshotWithDistance | nil. nil if no creature of that kind exists.
- api.get_block(x, y, z): The block at an integer position. Returns string. Snake_case block id -- see block_kinds. Positions outside the loaded/generated world, or above/below the vertical bounds, read as "air", never an error.
- api.find_blocks(kind, cx, cy, cz, radius): Positions of every block of one kind within a radius of a point. kind: A block id from block_kinds, OR the special category alias "wood" (matches any tree species: oak_wood, spruce_wood, birch_wood, cherry_wood). Unlike find_creatures' kind, an unrecognized string here returns an EMPTY result, not "match everything" -- this asymmetry is a real gotcha, not a design you can rely on being consistent across query methods. radius: Clamped into [0, find_radius_max]. Returns BlockPos[]. Up to find_results_max entries; excess matches are silently dropped.
- api.terrain_height(x, z): The integer y of the topmost solid ground block at a column. Useful for placing/spawning things at the correct height instead of guessing. Returns integer.
- api.distance(x1, y1, z1, x2, y2, z2): Straight-line distance between two points. Prefer this over writing your own sqrt(dx*dx+dy*dy+dz*dz). Returns number.
- api.get_behavior(creature_id): Overrides persist until changed and survive save/reload; disabling a rule does not undo them. Read current behavior settings: aggressive boolean, mode (auto/chase/attack/ignore), optional target_type (player/creature) and target_id. Nil for missing creature. Target fields describe explicit selection, not automatic aggro. Attack mode is intent, not proof an attack landed. Returns table|nil. Behavior settings or nil.
- api.get_resource_count(player_id, kind): Read a resource count for any connected player, including guests. Includes staged inventory changes and earlier accepted callbacks. Returns integer | nil. 0 means none held; nil means unknown player or invalid/noncollectible resource.
- api.get_inventory(player_id): Legacy resource-only inventory map, including zeros and staged changes. Use get_player_inventory for resources, equipment, elements and mana together. Editing returned tables changes nothing. Returns table | nil. Resource ID to count table, or nil for a missing player.
- api.has_resource(player_id, kind, amount): Whether a connected player holds at least amount of a collectible resource. Amount defaults to 1 when omitted. To check absence use api.has_resource(id, kind) == false; nil means invalid input, not absence. amount: Positive minimum count; default 1. Returns boolean | nil. True if sufficient, false if insufficient, nil for unknown player/resource or zero amount. Negative/nonfinite amounts fail validation.
- api.has_item(player_id, kind, amount): Checks equipment IDs axe/pickaxe/sword/bow or collectible resource IDs. Omitted amount defaults to 1; false means insufficient count, nil means missing player or invalid ID/amount. Includes staged changes. Returns boolean | nil. Same semantics as has_resource.
- api.instant_mana_cost: integer. Engine cost per successful instant cast: normally 5, or 0 with host mana-free testing enabled. Reserved before on_cast and refunded on failure. Do not charge again in Lua.
- api.rule_mana_cost: integer. Engine cost for successful generated rule creation: normally 20, or 0 with host mana-free testing enabled. Charged once to its author, no ongoing upkeep.
- api.mana_regen_cap: integer. Passive recovery cap: 100. Connected players gain 1 mana every 5 seconds. Explicit grants/conversion may exceed the cap.
- api.is_raining: boolean. True in rain or storm; refreshes after set_weather within a callback.
- api.campfire_light_radius: number. Campfire maximum illumination radius: 8 blocks.
- api.fish_spawn_clearance: integer. Required water cells beyond the fish center in each horizontal direction: 3 (a full 7x7 layer plus body clearance).
- api.time_of_day: number. 0 = sunrise, 0.25 = noon, 0.5 = sunset, 0.75 = midnight.
- api.is_night: boolean. True once the sun is below the horizon (matches the point the sky finishes fading to full night).
- api.weather: string. Current weather. sunny is the baseline (weighted heaviest when the engine picks the next weather on its own timer -- see set_weather). storm and windy both increase grass/leaf wind-sway noticeably (storm the most); mist reduces it and hazes the fog color. Only rain and storm render falling rain. "clear" is still accepted by set_weather as an alias for "sunny" (see set_weather), but this property itself only ever reports the current name, "sunny". One of: sunny, rain, mist, storm, windy.

Table shapes -- PlayerJournal, QuestProgress, PlayerSnapshot, PlayerSnapshotWithDistance, CreatureSnapshot, CampfireSnapshot, WaterSnapshot, WaterfallSnapshot, CreatureSnapshotWithDistance, BlockPos, CastEvent, DeathEvent, BlockBreakEvent, InteractEvent (fields with a caveat noted inline):
- PlayerJournal = {stage [Completed contracts, 0..3: gather supplies, explore underground, craft a tool. Three means all complete.], title [Current contract name, or Wayfinder after completion.], explored_depths [Explored roofed underground air at Y 2..12 while on contract two.], crafted_tool [Successfully crafted a new sword through the player crafting transaction while on contract three. Legacy tool completion credit is retained.], recoveries [Number of automatic recoveries from defeat.], complete, home [Recovery feet cell with integer x/y/z; nil before a home is established.], quests_completed [Number of rewarded traveler quests, 0..20; independent of the three campkeeper contracts.], quests [Array of twenty QuestProgress rows, in stable ID order. Delivery progress reflects current inventory; other objectives remember host-observed actions. Reward claims require a living player near the named NPC.]}
- QuestProgress = {id [Stable quest ID, 1..20.], npc [Sage, Elf Ranger, Warrior, Merchant, Fire Sorceress, or Necromancer.], title, objective, progress [Current delivery stock or recorded successful actions, capped at target.], target, completed [Reward has been claimed; cannot be claimed again. Delivery counts may fall after turn-in.]}
- PlayerSnapshot = {id [Stable per-connection player id; 0 is always the host.], mana [Available mana including staged changes; use get_player_inventory for equipment and element tables.], x, y, z, carrying_crystal [True once this player has ever broken a Crystal block this session. One-shot: never resets to false from this API (there is no 'drop crystal' action).], speed [Horizontal speed in blocks/sec -- excludes vertical (fall/jump) motion.], vertical_speed [Signed vertical speed: positive while rising (e.g. jumping), negative while falling.], on_ground [True when standing on solid ground. Never true the same tick vertical_speed is positive -- a jump sets both at once, so 'on_ground and vertical_speed > 0' can never be true. There is no separate on_jump/on_land event; detect a one-shot transition by remembering the previous tick's on_ground per player id.], running [True while sprinting, as opposed to walking.], in_water [True while standing in a water block.], health [0-100. Host vitals persist in current saves. Zero starts automatic three-second recovery; resources and journal progress are retained (see persistence.player_state_not_saved).], poisoned [While true, this player loses 1 health every poison_tick_secs, until something sets it back to false (e.g. a future medication item -- see set_poisoned). Sourced from and reported through this flag only; there is no separate 'poison timer' exposed.], speed_multiplier [Multiplies this player's base walk/sprint speed. 1.0 = normal; see set_player_speed.], jump_multiplier [Multiplies this player's base jump speed (so roughly jump *height* scales with its square, not linearly). 1.0 = normal; see set_player_jump.], oxygen [0-100. Drains by oxygen_drain_per_sec while this player is standing in a water block, regenerates by oxygen_regen_per_sec otherwise, capping at 100 when not submerged. Once it reaches 0 and stays there, health starts draining too (drowning_damage_per_sec) -- pure engine state, purely a function of being in water; there is no api.set_player_oxygen, nothing else moves this value.]}
- PlayerSnapshotWithDistance = PlayerSnapshot + {distance}
- CreatureSnapshot = {id [Stable creature id, valid until it despawns (destroy/damage-to-zero).], kind, x, y, z, health, max_health [Fixed per kind (sheep 12, chicken 6, stone_golem 40, wolf 18, stinger 14, cow 20, goblin 24, sunscorch 28, zombie 24, skeleton 18, dragon_green/dragon_red 240, fish 4); never changes at runtime.], can_swim [True for fish; indicates dedicated swimming behavior, not incidental immersion.], can_fly [True for dragons; capability, not current flight state.], in_water [Creature center currently occupies water, including staged block edits. Fish may be false during a surface jump.]}
- CampfireSnapshot = {x, y, z, burning [True while supported by solid ground. Rain does not extinguish it.], light_radius [Maximum light range, 8 blocks.], light_active [Supported and api.is_night; renderer also fades through twilight.], requires_fuel [Always false.]}
- WaterSnapshot = {x, y, z, surface_y [Top surface coordinate, one above the highest connected water block.], depth [Number of vertically contiguous water blocks.], flowing [True for classified river/stream currents; false in lakes and unclassified water.], flow_x [Unit horizontal current direction, or zero when still.], flow_z, flow_speed [Visual animation speed: 1.4 when flowing, otherwise 0. No movement force.], visual_only [Always true.]}
- WaterfallSnapshot = {x, y, z, bottom_y [Receiving water surface coordinate.], height [Drop of 2 through 16 blocks.], flow_x, flow_z, sound_radius [48 blocks; audio remains local and bounded.], visual_only [Always true; not a fluid entity or collectible block.]}
- CreatureSnapshotWithDistance = CreatureSnapshot + {distance}
- BlockPos = {x, y, z}
- CastEvent = {player_id [id of the player who clicked Run (matches PlayerSnapshot.id). Only the host can run a spell, so this is currently always the host's id, but treat it as any connected player's id -- don't hardcode 0.]}
- DeathEvent = {kind, x [Last position before death.], y, z}
- BlockBreakEvent = {kind [Snake_case id of the block that was broken -- see block_kinds. Same vocabulary as get_block's return value.], x, y, z, player_id [id of the player who broke it (matches PlayerSnapshot.id).]}
- InteractEvent = {kind [Snake_case id of the block interacted with -- see block_kinds. Same vocabulary as get_block's return value.], x, y, z, player_id [id of the player who interacted (matches PlayerSnapshot.id).]}

Actions (budget-limited per call: 32 block edits, 4 creature spawns -- an on_cast call gets higher budgets instead, 300 block edits and 30 creature spawns, since it runs once rather than ~10/sec; failures are silent -- check return values, not errors):
- api.give_mana(player_id, amount): Grant mana as an explicit rule reward. Not automatic recovery. Amount must be 1..item_grant_max; false on invalid player, amount or overflow. Returns boolean.
- api.take_mana(player_id, amount): Reserve an additional custom mana cost; false leaves balances unchanged if insufficient. With host mana-free testing enabled, valid requests succeed without reducing mana. Do not charge the engine instant/rule fee again. Amount 1..item_grant_max. Returns boolean.
- api.give_element(player_id, element, amount): Grant an explicit elemental reward. Names earth/fire/water/life/death are case insensitive. Amount 1..item_grant_max; invalid input/overflow returns false. Returns boolean.
- api.take_element(player_id, element, amount): Consume elements atomically; false if invalid input or insufficient balance. Amount 1..item_grant_max. Returns boolean.
- api.craft_item(player_id, kind, amount): Create one axe, pickaxe, sword or bow using the same iron/oak_wood/mana formula as inventory. Optional amount defaults to 1 and must equal 1. No free gear grant. Read get_item_recipe first. Returns boolean.
- api.decompose_item(player_id, kind, amount): Consume one owned axe/pickaxe/sword/bow and its mana cost; return salvaged iron and oak_wood per get_item_recipe. Optional amount must equal 1. Returns boolean.
- api.decompose_resource(player_id, kind, amount): Consume 1..item_grant_max resource units and the same amount of mana, granting their catalog elements. Optional amount defaults to 1. False on invalid inputs, missing resources/mana or overflow; no partial changes. Returns boolean.
- api.convert_elements_to_mana(player_id, element, amount): Convert elements into mana at the host crafting registry conversion rate. Amount 1..item_grant_max, default 1. No additional mana fee. False if invalid/insufficient/overflow. Returns boolean.
- api.place_campfire_near_player(player_id, radius): Preferred for create campfire nearby / near me (including obvious typos such as camfpire). Call once in on_cast with event.player_id and radius 6. Searches real loaded edited ground within radius and +/-4 vertical blocks; avoids players by 2 horizontal blocks, requires support and fire/smoke clearance, may replace a small ground plant. No guessed terrain_height or spawn_creature calls. radius: Clamped to 2..8 blocks; 6 recommended. Returns CampfireSnapshot | nil. Placed campfire position/state, or nil for missing player, no safe site or exhausted block budget. Uses one shared block edit; searches observe staged edits and roll back on callback failure.
- api.set_device_enabled(x, y, z, enabled): Enable or pause an automation device without losing its paid cycle, stored mana or items. For example, disable condensers at night. Transactional: errors roll back changes. Costs one shared block-edit budget unit. Returns boolean. False if absent or budget exhausted.
- api.configure_device(x, y, z, settings): Update supplied settings only: enabled, recipe (existing crafting recipe ID), element (earth/fire/water/life/death), reserve, input (west/east/north/south/up/down), outputs (ordered face array), routing (round_robin/priority/filter), filter (matter ID), sensor_x/sensor_y/sensor_z, sensor_item (empty for total), lower, upper, signal_mode (state/pulse/numeric), invert, valve_matter, eject_contents (chest/smelter: true ejects bags/living creatures nearby, false stores or feeds through its output port; defaults true). Lower must be below upper. Sensor targets a chest or vessel within 16 blocks. An inverted valve opens while signal is off for upper/lower stock control. Ports rotate with the device; inputs and outputs must differ. Current paid cycles retain their recipe. One shared block-edit budget unit; rollback on callback error. Returns boolean. False for absent device, invalid settings or exhausted budget.
- api.place_device(player_id, kind, x, y, z, rotation): Build an automation device within 7 blocks of a connected player, paying resource costs from their inventory. Kinds: collector, vessel, condenser, dissipator, conduit, channel, splitter, chest, workshop, sensor, valve, signal, smelter, lantern, dark_altar, shrine. Rotation is 0..3 clockwise quarter-turns. Footprints are one block; lantern is 3 blocks high, dark_altar and shrine 2, others 1. Checks clearance over full height, player collision, limits and funds. Opposing same-type ports connect automatically at the base. Lantern uses 1 mana per 10 seconds for white-blue light. Dark altar damages and shrine heals all creatures within radius 6 by 3 health each second, costing 1 mana per second. They accept personal refills through F and mana input on horizontal/bottom base faces. Uses one shared block-edit budget; inventory and placement roll back on callback failure. Returns boolean. True when staged, false for invalid placement, missing funds/player or exhausted budget.
- api.place_campfire(x, y, z): Place an indefinitely burning campfire on loaded grass, soil, sand, or stone with four air blocks above the support. Uses one shared block edit; no recipe or inventory cost. Returns boolean. False for occupied, unsupported, unloaded, out-of-height, or exhausted-budget sites. To remove, replace_block(x,y,z,'air').
- api.spawn_fish(x, y, z): Spawn a swimming fish only where can_spawn_fish succeeds. Reads staged water edits and shares the normal creature spawn budget, including failed attempts. Use chase(id,x,y,z) each tick to guide it within connected water. Returns integer | nil. Stable creature id, or nil when habitat is unsuitable or spawn/entity budget is exhausted.
- api.chase(creature_id, x, y, z): Makes a creature move toward a point at increased speed, overriding explicit targeting and suppressing automatic attacks while the chase lease is active. Call it again every tick to keep it chasing -- stop calling it and the creature reverts to normal wandering within about a third of a second (use ignore to stop chasing). Returns nil. Always nil, even if creature_id doesn't exist -- there is no way to tell from Lua whether the call actually found the creature.
- api.protect_player(player_id, kind): On_tick only: prevent melee damage/attack animation from creature kind against this player without changing creature aggression or creature-to-creature combat. Rule-owned temporary policy: refresh every tick while condition holds; an empty next tick removes it. Disable/delete/error releases it; other rules' protections remain. Saved rules recompute policies after reload. Returns boolean. False for unknown player/species, true otherwise.
- api.suppress_creature_attacks(creature_id): On_tick only: temporarily prevent this creature's melee attacks against all targets. Same rule-owned cleanup as protect_player. Does not change underlying aggression, target or movement. Refresh only while the condition holds. Returns boolean. False for missing creature.
- api.set_aggressive(creature_id, aggressive): Set automatic player aggression, cancel explicit targeting and restore normal wandering/automatic AI. False makes even hostile species peaceful. True lets passive species attack too (2 damage, 1.5 reach, 2 second cooldown, 16 block detection). Returns boolean. False for missing IDs or invalid targets.
- api.set_target(creature_id, target_type, target_id): Select a specific live target without starting an action. target_type must be player or creature. Self-targets are rejected. Follow with attack or chase_target. Returns boolean. False for missing IDs or invalid targets.
- api.select_target(creature_id, kind, radius): Select nearest live target of kind player, sheep, chicken, cow, wolf, stone_golem, stinger, goblin, sunscorch, zombie, skeleton, dragon_green, dragon_red, or fish within radius (clamped to query limit). Excludes self. Returns target ID or nil; no match clears selection. Does not start an action; follow with attack or chase_target. Returns integer|nil. Selected ID or nil.
- api.chase_target(creature_id): Follow selected live target as it moves, without attacking; overrides built-in hostility. Returns false without a target. Returns boolean. False for missing IDs or invalid targets.
- api.attack(creature_id): Pursue selected live target and deal damage in melee range on species cooldown, including creature versus creature. Passive species can attack. Does not deal instant damage; use damage for that. Returns false without target. Returns boolean. False for missing IDs or invalid targets.
- api.ignore(creature_id): Cancel target, chase and aggression; resume peaceful wandering. Overrides built-in hostile AI. Use set_aggressive to restore automatic behavior. Returns boolean. False for missing IDs or invalid targets.
- api.die(creature_id): Kill creature immediately with normal death sound, despawn and on_death event, like destroy. Returns false if already dead or missing. Returns boolean. False for missing IDs or invalid targets.
- api.damage(creature_id, amount): Reduces a creature's health. Fires on_death (to every module, not just the caller) if this brings health to zero or below, and despawns it. Returns nil. Always nil, whether or not creature_id exists.
- api.destroy(creature_id): Removes a creature immediately regardless of remaining health, and fires on_death. Returns nil. Always nil, whether or not creature_id exists.
- api.spawn_creature(kind, x, y, z): Spawns a new creature at a position. sheep/chicken/cow are passive by default; set_aggressive or attack can enable combat. stone_golem, wolf, stinger, goblin, sunscorch, zombie, skeleton, dragon_green, and dragon_red are different: all nine hostile entirely on their own, with no Lua involved -- each closes on and periodically damages the nearest player within its own aggro radius. stone_golem is large, slow, and hits hardest on the longest cooldown; sunscorch is a rare, tanky ghost that never gives up a chase and (like stone_golem) never speeds up while chasing -- no run animation, mechanically identical pace whether wandering or aggroed; goblin is a mid-weight melee bruiser (moderate speed/damage/cooldown, tankier than wolf); wolf is faster and lighter; stinger is fastest to attack (shortest cooldown) but hits lightest and is the most fragile. Zombies and skeletons only walk, including while chasing, and use melee attacks. Dragons are giant solitary predators: they walk, take off, fly and attack in either mode, and land again. Dragon homes must be at least 320 blocks apart across both colors; spawn returns nil inside another dragon territory, including earlier spawns in the same callback. Dragons stay within 64 blocks of home even during scripted chases. Fish are passive swimmers: they require a full 7x7 horizontal water area centered on the spawn position (three water blocks in each horizontal direction), including water around their whole body. Fish spawns in smaller pools or on land return nil. Fish only swim through connected water and occasionally jump straight up and return to the same water column. Fish never attack, even if aggression is enabled. Only spawn a hostile one when a hostile/dangerous creature is actually what the request wants. kind: "sheep", "chicken", "stone_golem", "wolf", "stinger", "cow", "goblin", or "sunscorch", "zombie", "skeleton", "dragon_green", "dragon_red", "fish"; anything else (including a typo) silently becomes "sheep" -- not an error. Returns integer | nil. The new creature's id, or nil if this call's spawn budget is already used up or a dragon would violate territory spacing, or a fish lacks sufficient water.
- api.spawn_creature_near_player(player_id, kind, radius): Spawns a new creature at a random point within radius blocks of a player (horizontally; height snaps to terrain). For fish, searches nearby loaded water instead, requiring the same pool-size check as spawn_creature; returns nil if no suitable pool is found. Prefer this over spawn_creature plus your own random offset when the rule is about spawning near a specific player. kind: Same kinds as spawn_creature, including zombie, skeleton, dragon_green and dragon_red. Use these exact singular identifiers, not model variant filenames, plurals or dragon. Unknown strings silently spawn sheep. radius: Clamped into [1, find_radius_max] -- note the floor is 1, not 0, unlike the find_* methods. Returns integer | nil. The new creature's id, or nil for a missing player, exhausted spawn budget, creature population cap, insufficient fish habitat, or dragon territory overlap. Both dragon colors share a 320-block minimum home spacing, including spawns staged in this callback; nearby dragon packs cannot be spawned. Check for nil before using the id.
- api.replace_block(x, y, z, kind): Changes one block. kind: A block id from block_kinds (e.g. "air" to clear a block). Returns boolean. false if kind isn't a recognized block id, y is outside the world's vertical bounds, or the block-edit budget is used up. true means the edit was staged; it is applied only if the callback commits.
- api.set_weather(name): Sets the weather directly, and resets the engine's own random weather timer (so it won't immediately pick something else out from under you). name: "clear" is also accepted, as an alias for "sunny" (its name before the 5-weather system existed). Returns nil. An unrecognized name is silently ignored -- not an error.
- api.start_rain(): Shorthand for set_weather("rain"). Returns nil.
- api.stop_rain(): Shorthand for set_weather("sunny"). Returns nil.
- api.set_time_of_day(t): Sets the time of day directly. t: Wrapped into [0,1) (e.g. -0.25 and 1.25 both become 0.75), same scale as api.time_of_day. Returns nil.
- api.set_time_dawn(): Shorthand for set_time_of_day(0.0). Returns nil.
- api.set_time_night(): Shorthand for set_time_of_day(0.5) -- sunset, night begins. Returns nil.
- api.broadcast(message): Queues a notification and server log message, emitted only if the callback commits. At most 8 messages per callback, each at most 512 UTF-8 bytes; exceeding either limit aborts execution with an uncatchable budget failure. Returns nil.
- api.give_item(player_id, kind, amount): Grants collectible resources or equipment IDs axe/pickaxe/sword/bow into a connected player inventory, bypassing crafting costs. Equipment amounts must be 1..item_grant_max and overflow is rejected; legacy resource grants clamp the amount and saturate balances. Only use this when the request explicitly asks to add to a player's inventory/resources -- for everything else ("add 100 stone", "fill this area with water"), prefer replace_block to place blocks in the world instead. player_id: Target player (matches PlayerSnapshot.id). kind: A collectible resource ID or equipment ID axe/pickaxe/sword/bow. Air, water and campfire are not inventory stacks. amount: Resource grants clamp into [0, item_grant_max]; equipment requires 1..item_grant_max. Returns boolean. false for invalid ID/player/amount or equipment overflow. True stages the grant.
- api.take_item(player_id, kind, amount): Atomically remove collectible resources or equipment IDs axe/pickaxe/sword/bow from any connected player. Includes staged changes; failure rolls back. Equipment amounts must be 1..item_grant_max. This consumes items without decomposition returns. Returns boolean. False for missing player, invalid resource or insufficient count. True reserves the full amount.
- api.damage_player(player_id, amount): Reduces a player's health, clamped at 0 -- there is no death/respawn system yet, so health just stops there. Returns boolean. false if player_id isn't connected, true otherwise.
- api.heal_player(player_id, amount): Restores a player's health, clamped at 100 (max_health). Returns boolean. false if player_id isn't connected, true otherwise.
- api.set_poisoned(player_id, poisoned): Sets a player's poisoned flag directly -- true starts the 1-health-per-poison_tick_secs drain (see PlayerSnapshot.poisoned), false stops it (the hook a future medication item/effect would call; nothing in the engine calls this with false on its own yet). Returns boolean. false if player_id isn't connected, true otherwise.
- api.set_player_speed(player_id, multiplier): Sets a player's speed_multiplier (applied to their base walk/sprint speed). multiplier: Clamped into [attribute_multiplier_min, attribute_multiplier_max]. Returns boolean. false if player_id isn't connected, true otherwise.
- api.set_player_jump(player_id, multiplier): Sets a player's jump_multiplier (applied to their base jump speed). multiplier: Clamped into [attribute_multiplier_min, attribute_multiplier_max]. Returns boolean. false if player_id isn't connected, true otherwise.
- api.teleport_player(player_id, x, y, z): Moves a player straight to a position, bypassing normal movement and collision entirely (the same way replace_block bypasses mining). Resets that player's velocity to zero, so they don't keep carrying whatever momentum they had right before the jump. Returns boolean. false if player_id isn't connected, true otherwise.

function on_tick(api) [required]: Defines a RULE module. Required unless the module defines on_cast instead -- a module must define EXACTLY ONE of on_tick or on_cast, never both, never neither; Module::load rejects any other combination.
function on_cast(api, event) [optional]: Defines an INSTANT SPELL module instead of a RULE: a one-time immediate action with no ongoing condition to check (e.g. "add 100 stone", "spawn a dozen chickens around me", "heal me"), as opposed to a RULE's continuous "when/if/at night/while ..." behavior. Mutually exclusive with on_tick -- see on_tick's desc. Since it only runs once per click instead of ~10/sec, its per-call action budgets are higher than a RULE's -- see block_edits_per_cast_call and creature_spawns_per_cast_call.
function on_death(api, event) [optional]: Fires once per creature death, from any cause (this module's or another enabled module's api.damage/api.destroy). Does NOT chain: if an on_death handler itself kills another creature, that second death does not fire on_death again within the same tick.
function on_block_break(api, event) [optional]: Fires once per real player-caused block break (mining). A rule's own replace_block calls, even ones that set a block to air, never trigger this.
function on_interact(api, event) [optional]: Fires once per real player-caused interact-key press (E) aimed at a block, whether or not anything is actually done in response -- the non-destructive counterpart to on_block_break, for a rule that reacts to a player deliberately using/examining something (e.g. a crystal that heals on touch) rather than mining it. Never fires from a rule's own replace_block calls, and never changes the block itself.

Every World API call executes ONLY on the host -- Lua does not run on joined clients at all (ScriptHost is host-only state). A module's effects (block edits, creature spawns/state, weather, time of day, broadcasts, item grants, player attributes, player teleports) reach clients purely through the replication channels below; there is no separate "multiplayer mode" a rule opts into. Only the host can generate, activate, or run a module (a menu/UI restriction, not something this API itself enforces or exposes) -- so an on_cast's `event.player_id` is currently always the host's own id, even though the API shape allows for any player.
