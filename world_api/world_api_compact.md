World API v1.16.0 (the `api` table passed into on_tick/on_cast/on_death/on_block_break/on_interact)

Source is limited to 65,536 UTF-8 bytes. Initialization and every callback each receive 100,000 Lua instructions and a 5ms wall-time budget. Hooks check every 1,000 instructions; API entry/exit and execution completion also check time. Limits reset for each invocation. Budget exhaustion cannot be caught or suppressed with pcall/xpcall; ordinary Lua errors remain catchable. Native operations are not forcibly interrupted, so the time budget is a cooperative limit, not a hard realtime deadline. Each host tick/cast dispatch admits at most 16 callbacks under shared ceilings of 400,000 instructions, 4,096 API calls, 262,144 native work units and 20ms cooperative time. Admission reserves the full per-callback allowance (plus initialization for a failed VM reload); unstarted work waits for a later dispatch without resetting or replaying the callback. Native work is limited to 65,536 units per callback: find_blocks charges its bounding cube candidates times (1 + staged block edits); other methods charge 1 + creature count + player count + staged player effects + staged block edits. find_blocks also checks time between scan rows. These units conservatively bound repeated scans, not CPU instructions or hard realtime.
Pending callbacks use round-robin recipient queues, FIFO within each rule. Tick requests coalesce to one pending tick per rule. Events retain their original recipient and payload, but query current world state when run. Disabling/deleting a rule cancels its queued work. Re-enabling a rule or adding a new rule never delivers old events to that new activation. Queues hold at most 512 callbacks total and 64 per module; newest excess requests are dropped with a visible saturation notice. Only the first 512 incoming block-break events and first 512 interactions per dispatch are considered. Queues are transient and are not saved on world exit. Up to 64 modules are loaded; saved overflow or invalid source is preserved without execution and reported to the host. Removing loaded modules and reloading the world can make room for preserved overflow modules.
World API spawns return nil at 256 live creatures (including starter creatures); destroying one frees capacity.
All API methods share 512 calls per callback; exceeding this aborts execution. Coordinates must be within +/-1000000 blocks; all numeric arguments must be finite f32 values.
Each callback is one transaction. Block edits, creature spawning/chasing/ damage/destruction, player effects, inventory changes, weather (including its RNG/timer), time, and broadcasts are staged. Queries read the callback's own accepted writes plus earlier successful callbacks in the same host dispatch. Returned query tables are snapshots; query again after an action. time_of_day/is_night/weather properties refresh after API calls. Movement and physics are not simulated during a callback; terrain_height remains the procedural generator height, not a scan of edited blocks. Failed callbacks emit no death events, broadcasts, replication effects, or spawn ID/RNG advances. Successful callbacks commit in scheduler order. Death events enqueue one level of notifications only after their cause commits. A failing death handler rolls back only its own changes, not the earlier death that triggered it. Ordinary errors caught by Lua do not abort the transaction; instruction/time/API/native-work/broadcast budget failures cannot be caught. This is callback failure rollback, not user-facing history/undo or atomic network delivery. Shared admission bounds callback work; native commit/apply and operating-system scheduling can overrun the cooperative wall-time target.

Queries:
- api.players(): Every connected player. Returns PlayerSnapshot[]. Empty array if nobody is connected.
- api.nearest_player(x, y, z): The single closest connected player to a point. Prefer this over looping players() yourself when you just need the closest one. Returns PlayerSnapshotWithDistance | nil. nil if no players are connected.
- api.creatures(): Every creature in the world. Returns CreatureSnapshot[]. Empty array if none exist.
- api.find_creatures(kind, cx, cy, cz, radius): Creatures of one kind within a radius of a point. kind: "sheep", "chicken", "stone_golem", "wolf", "stinger", "cow", "goblin", "sunscorch", or "any". An unrecognized string is treated the same as "any" -- it is NOT an error, so a typo silently matches every creature instead of failing loudly. radius: Clamped into [0, find_radius_max]. Returns CreatureSnapshot[]. Up to find_results_max entries; excess matches are silently dropped.
- api.nearest_creature(kind, x, y, z): The single closest creature of one kind to a point. No radius argument -- it searches every creature in the world unconditionally. kind: "sheep", "chicken", "stone_golem", "wolf", "stinger", "cow", "goblin", "sunscorch", or "any" -- same unrecognized-string-means-any behavior as find_creatures. Returns CreatureSnapshotWithDistance | nil. nil if no creature of that kind exists.
- api.get_block(x, y, z): The block at an integer position. Returns string. Snake_case block id -- see block_kinds. Positions outside the loaded/generated world, or above/below the vertical bounds, read as "air", never an error.
- api.find_blocks(kind, cx, cy, cz, radius): Positions of every block of one kind within a radius of a point. kind: A block id from block_kinds, OR the special category alias "wood" (matches any tree species: oak_wood, spruce_wood, birch_wood, cherry_wood). Unlike find_creatures' kind, an unrecognized string here returns an EMPTY result, not "match everything" -- this asymmetry is a real gotcha, not a design you can rely on being consistent across query methods. radius: Clamped into [0, find_radius_max]. Returns BlockPos[]. Up to find_results_max entries; excess matches are silently dropped.
- api.terrain_height(x, z): The integer y of the topmost solid ground block at a column. Useful for placing/spawning things at the correct height instead of guessing. Returns integer.
- api.distance(x1, y1, z1, x2, y2, z2): Straight-line distance between two points. Prefer this over writing your own sqrt(dx*dx+dy*dy+dz*dz). Returns number.
- api.get_behavior(creature_id): Overrides persist until changed and survive save/reload; disabling a rule does not undo them. Read current behavior settings: aggressive boolean, mode (auto/chase/attack/ignore), optional target_type (player/creature) and target_id. Nil for missing creature. Target fields describe explicit selection, not automatic aggro. Attack mode is intent, not proof an attack landed. Returns table|nil. Behavior settings or nil.
- api.get_resource_count(player_id, kind): Read a resource count for any connected player, including guests. Includes staged inventory changes and earlier accepted callbacks. Returns integer | nil. 0 means none held; nil means unknown player or invalid/noncollectible resource.
- api.get_inventory(player_id): Return a detached table mapping all collectible resource IDs to counts, including zeros, for any connected player. Includes staged changes. Editing this table does not modify inventory. Equipment/items outside the resource catalog are not implemented. Returns table | nil. Resource ID to count table, or nil for a missing player.
- api.has_resource(player_id, kind, amount): Whether a connected player holds at least amount of a collectible resource. Amount defaults to 1 when omitted. To check absence use api.has_resource(id, kind) == false; nil means invalid input, not absence. amount: Positive minimum count; default 1. Returns boolean | nil. True if sufficient, false if insufficient, nil for unknown player/resource or zero amount. Negative/nonfinite amounts fail validation.
- api.has_item(player_id, kind, amount): Alias of has_resource for the current resource inventory. No separate equipment-item system exists. Omitted amount defaults to 1; compare result to false to check absence without confusing nil with empty inventory. Returns boolean | nil. Same semantics as has_resource.
- api.time_of_day: number. 0 = sunrise, 0.25 = noon, 0.5 = sunset, 0.75 = midnight.
- api.is_night: boolean. True once the sun is below the horizon (matches the point the sky finishes fading to full night).
- api.weather: string. Current weather. sunny is the baseline (weighted heaviest when the engine picks the next weather on its own timer -- see set_weather). storm and windy both increase grass/leaf wind-sway noticeably (storm the most); mist reduces it and hazes the fog color. Only rain and storm render falling rain. "clear" is still accepted by set_weather as an alias for "sunny" (see set_weather), but this property itself only ever reports the current name, "sunny". One of: sunny, rain, mist, storm, windy.

Table shapes -- PlayerSnapshot, PlayerSnapshotWithDistance, CreatureSnapshot, CreatureSnapshotWithDistance, BlockPos, CastEvent, DeathEvent, BlockBreakEvent, InteractEvent (fields with a caveat noted inline):
- PlayerSnapshot = {id [Stable per-connection player id; 0 is always the host.], x, y, z, carrying_crystal [True once this player has ever broken a Crystal block this session. One-shot: never resets to false from this API (there is no 'drop crystal' action).], speed [Horizontal speed in blocks/sec -- excludes vertical (fall/jump) motion.], vertical_speed [Signed vertical speed: positive while rising (e.g. jumping), negative while falling.], on_ground [True when standing on solid ground. Never true the same tick vertical_speed is positive -- a jump sets both at once, so 'on_ground and vertical_speed > 0' can never be true. There is no separate on_jump/on_land event; detect a one-shot transition by remembering the previous tick's on_ground per player id.], running [True while sprinting, as opposed to walking.], in_water [True while standing in a water block.], health [0-100. Starts at 100 for every player every session -- like resources, health is NOT saved/reloaded with the world (see persistence.player_state_not_saved).], poisoned [While true, this player loses 1 health every poison_tick_secs, until something sets it back to false (e.g. a future medication item -- see set_poisoned). Sourced from and reported through this flag only; there is no separate 'poison timer' exposed.], speed_multiplier [Multiplies this player's base walk/sprint speed. 1.0 = normal; see set_player_speed.], jump_multiplier [Multiplies this player's base jump speed (so roughly jump *height* scales with its square, not linearly). 1.0 = normal; see set_player_jump.], oxygen [0-100. Drains by oxygen_drain_per_sec while this player is standing in a water block, regenerates by oxygen_regen_per_sec otherwise, capping at 100 when not submerged. Once it reaches 0 and stays there, health starts draining too (drowning_damage_per_sec) -- pure engine state, purely a function of being in water; there is no api.set_player_oxygen, nothing else moves this value.]}
- PlayerSnapshotWithDistance = PlayerSnapshot + {distance}
- CreatureSnapshot = {id [Stable creature id, valid until it despawns (destroy/damage-to-zero).], kind, x, y, z, health, max_health [Fixed per kind (sheep 12, chicken 6, stone_golem 40, wolf 18, stinger 14, cow 20, goblin 24, sunscorch 28); never changes at runtime.]}
- CreatureSnapshotWithDistance = CreatureSnapshot + {distance}
- BlockPos = {x, y, z}
- CastEvent = {player_id [id of the player who clicked Run (matches PlayerSnapshot.id). Only the host can run a spell, so this is currently always the host's id, but treat it as any connected player's id -- don't hardcode 0.]}
- DeathEvent = {kind, x [Last position before death.], y, z}
- BlockBreakEvent = {kind [Snake_case id of the block that was broken -- see block_kinds. Same vocabulary as get_block's return value.], x, y, z, player_id [id of the player who broke it (matches PlayerSnapshot.id).]}
- InteractEvent = {kind [Snake_case id of the block interacted with -- see block_kinds. Same vocabulary as get_block's return value.], x, y, z, player_id [id of the player who interacted (matches PlayerSnapshot.id).]}

Actions (budget-limited per call: 32 block edits, 4 creature spawns -- an on_cast call gets higher budgets instead, 300 block edits and 30 creature spawns, since it runs once rather than ~10/sec; failures are silent -- check return values, not errors):
- api.chase(creature_id, x, y, z): Makes a creature move toward a point at increased speed, overriding explicit targeting and suppressing automatic attacks while the chase lease is active. Call it again every tick to keep it chasing -- stop calling it and the creature reverts to normal wandering within about a third of a second (use ignore to stop chasing). Returns nil. Always nil, even if creature_id doesn't exist -- there is no way to tell from Lua whether the call actually found the creature.
- api.protect_player(player_id, kind): On_tick only: prevent melee damage/attack animation from creature kind against this player without changing creature aggression or creature-to-creature combat. Rule-owned temporary policy: refresh every tick while condition holds; an empty next tick removes it. Disable/delete/error releases it; other rules' protections remain. Saved rules recompute policies after reload. Returns boolean. False for unknown player/species, true otherwise.
- api.suppress_creature_attacks(creature_id): On_tick only: temporarily prevent this creature's melee attacks against all targets. Same rule-owned cleanup as protect_player. Does not change underlying aggression, target or movement. Refresh only while the condition holds. Returns boolean. False for missing creature.
- api.set_aggressive(creature_id, aggressive): Set automatic player aggression, cancel explicit targeting and restore normal wandering/automatic AI. False makes even hostile species peaceful. True lets passive species attack too (2 damage, 1.5 reach, 2 second cooldown, 16 block detection). Returns boolean. False for missing IDs or invalid targets.
- api.set_target(creature_id, target_type, target_id): Select a specific live target without starting an action. target_type must be player or creature. Self-targets are rejected. Follow with attack or chase_target. Returns boolean. False for missing IDs or invalid targets.
- api.select_target(creature_id, kind, radius): Select nearest live target of kind player, sheep, chicken, cow, wolf, stone_golem, stinger, goblin, or sunscorch within radius (clamped to query limit). Excludes self. Returns target ID or nil; no match clears selection. Does not start an action; follow with attack or chase_target. Returns integer|nil. Selected ID or nil.
- api.chase_target(creature_id): Follow selected live target as it moves, without attacking; overrides built-in hostility. Returns false without a target. Returns boolean. False for missing IDs or invalid targets.
- api.attack(creature_id): Pursue selected live target and deal damage in melee range on species cooldown, including creature versus creature. Passive species can attack. Does not deal instant damage; use damage for that. Returns false without target. Returns boolean. False for missing IDs or invalid targets.
- api.ignore(creature_id): Cancel target, chase and aggression; resume peaceful wandering. Overrides built-in hostile AI. Use set_aggressive to restore automatic behavior. Returns boolean. False for missing IDs or invalid targets.
- api.die(creature_id): Kill creature immediately with normal death sound, despawn and on_death event, like destroy. Returns false if already dead or missing. Returns boolean. False for missing IDs or invalid targets.
- api.damage(creature_id, amount): Reduces a creature's health. Fires on_death (to every module, not just the caller) if this brings health to zero or below, and despawns it. Returns nil. Always nil, whether or not creature_id exists.
- api.destroy(creature_id): Removes a creature immediately regardless of remaining health, and fires on_death. Returns nil. Always nil, whether or not creature_id exists.
- api.spawn_creature(kind, x, y, z): Spawns a new creature at a position. sheep/chicken/cow are passive by default; set_aggressive or attack can enable combat. stone_golem, wolf, stinger, goblin, and sunscorch are different: all five hostile entirely on their own, with no Lua involved -- each closes on and periodically damages the nearest player within its own aggro radius. stone_golem is large, slow, and hits hardest on the longest cooldown; sunscorch is a rare, tanky ghost that never gives up a chase and (like stone_golem) never speeds up while chasing -- no run animation, mechanically identical pace whether wandering or aggroed; goblin is a mid-weight melee bruiser (moderate speed/damage/cooldown, tankier than wolf); wolf is faster and lighter; stinger is fastest to attack (shortest cooldown) but hits lightest and is the most fragile. Only spawn a hostile one when a hostile/dangerous creature is actually what the request wants. kind: "sheep", "chicken", "stone_golem", "wolf", "stinger", "cow", "goblin", or "sunscorch"; anything else (including a typo) silently becomes "sheep" -- not an error. Returns integer | nil. The new creature's id, or nil if this call's spawn budget is already used up.
- api.spawn_creature_near_player(player_id, kind, radius): Spawns a new creature at a random point within radius blocks of a player (horizontally; height snaps to terrain). Prefer this over spawn_creature plus your own random offset when the rule is about spawning near a specific player. kind: Same silent-default-to-sheep behavior as spawn_creature. radius: Clamped into [1, find_radius_max] -- note the floor is 1, not 0, unlike the find_* methods. Returns integer | nil. The new creature's id, or nil if player_id isn't connected OR the spawn budget is used up -- these two failure cases are indistinguishable from Lua.
- api.replace_block(x, y, z, kind): Changes one block. kind: A block id from block_kinds (e.g. "air" to clear a block). Returns boolean. false if kind isn't a recognized block id, y is outside the world's vertical bounds, or the block-edit budget is used up. true means the edit was staged; it is applied only if the callback commits.
- api.set_weather(name): Sets the weather directly, and resets the engine's own random weather timer (so it won't immediately pick something else out from under you). name: "clear" is also accepted, as an alias for "sunny" (its name before the 5-weather system existed). Returns nil. An unrecognized name is silently ignored -- not an error.
- api.start_rain(): Shorthand for set_weather("rain"). Returns nil.
- api.stop_rain(): Shorthand for set_weather("sunny"). Returns nil.
- api.set_time_of_day(t): Sets the time of day directly. t: Wrapped into [0,1) (e.g. -0.25 and 1.25 both become 0.75), same scale as api.time_of_day. Returns nil.
- api.set_time_dawn(): Shorthand for set_time_of_day(0.0). Returns nil.
- api.set_time_night(): Shorthand for set_time_of_day(0.5) -- sunset, night begins. Returns nil.
- api.broadcast(message): Queues a notification and server log message, emitted only if the callback commits. At most 8 messages per callback, each at most 512 UTF-8 bytes; exceeding either limit aborts execution with an uncatchable budget failure. Returns nil.
- api.give_item(player_id, kind, amount): Grants items straight into a player's Resources inventory (the panel populated by hand-gathering blocks), bypassing the world entirely. Only use this when the request explicitly asks to add to a player's inventory/resources -- for everything else ("add 100 stone", "fill this area with water"), prefer replace_block to place blocks in the world instead. player_id: Target player (matches PlayerSnapshot.id). kind: A block id from block_kinds, but only the ones gatherable by hand (a resource, not e.g. "air" or "water") count -- anything else is rejected. amount: Clamped into [0, item_grant_max]. Returns boolean. false if kind isn't a grantable resource, player_id isn't connected, or amount clamped to 0 -- these failure cases are indistinguishable from Lua. true otherwise.
- api.take_item(player_id, kind, amount): Atomically remove resources from any connected player's authoritative inventory, including guests. Staged grants/removals and earlier committed callbacks are included; failed callbacks roll back. Returns boolean. False for missing player, invalid resource or insufficient count. True reserves the full amount.
- api.damage_player(player_id, amount): Reduces a player's health, clamped at 0 -- there is no death/respawn system yet, so health just stops there. Returns boolean. false if player_id isn't connected, true otherwise.
- api.heal_player(player_id, amount): Restores a player's health, clamped at 100 (max_health). Returns boolean. false if player_id isn't connected, true otherwise.
- api.set_poisoned(player_id, poisoned): Sets a player's poisoned flag directly -- true starts the 1-health-per-poison_tick_secs drain (see PlayerSnapshot.poisoned), false stops it (the hook a future medication item/effect would call; nothing in the engine calls this with false on its own yet). Returns boolean. false if player_id isn't connected, true otherwise.
- api.set_player_speed(player_id, multiplier): Sets a player's speed_multiplier (applied to their base walk/sprint speed). multiplier: Clamped into [attribute_multiplier_min, attribute_multiplier_max]. Returns boolean. false if player_id isn't connected, true otherwise.
- api.set_player_jump(player_id, multiplier): Sets a player's jump_multiplier (applied to their base jump speed). multiplier: Clamped into [attribute_multiplier_min, attribute_multiplier_max]. Returns boolean. false if player_id isn't connected, true otherwise.
- api.teleport_player(player_id, x, y, z): Moves a player straight to a position, bypassing normal movement and collision entirely (the same way replace_block bypasses mining). Resets that player's velocity to zero, so they don't keep carrying whatever momentum they had right before the jump. Returns boolean. false if player_id isn't connected, true otherwise.

function on_tick(api) [required]: Defines a RULE module. Required unless the module defines on_cast instead -- a module must define EXACTLY ONE of on_tick or on_cast, never both, never neither; Module::load rejects any other combination.
function on_cast(api, event) [optional]: Defines an INSTANT SPELL module instead of a RULE: a one-time immediate action with no ongoing condition to check (e.g. "add 100 stone", "spawn a dozen chickens around me", "heal me"), as opposed to a RULE's continuous "when/if/at night/while ..." behavior. Mutually exclusive with on_tick -- see on_tick's desc. Since it only runs once per click instead of ~10/sec, its per-call action budgets are higher than a RULE's -- see block_edits_per_cast_call and creature_spawns_per_cast_call.
function on_death(api, event) [optional]: Fires once per creature death, from any cause (this module's or another enabled module's api.damage/api.destroy). Does NOT chain: if an on_death handler itself kills another creature, that second death does not fire on_death again within the same tick.
function on_block_break(api, event) [optional]: Fires once per real player-caused block break (mining). A rule's own replace_block calls, even ones that set a block to air, never trigger this.
function on_interact(api, event) [optional]: Fires once per real player-caused interact-key press (E) aimed at a block, whether or not anything is actually done in response -- the non-destructive counterpart to on_block_break, for a rule that reacts to a player deliberately using/examining something (e.g. a crystal that heals on touch) rather than mining it. Never fires from a rule's own replace_block calls, and never changes the block itself.

Every World API call executes ONLY on the host -- Lua does not run on joined clients at all (ScriptHost is host-only state). A module's effects (block edits, creature spawns/state, weather, time of day, broadcasts, item grants, player attributes, player teleports) reach clients purely through the replication channels below; there is no separate "multiplayer mode" a rule opts into. Only the host can generate, activate, or run a module (a menu/UI restriction, not something this API itself enforces or exposes) -- so an on_cast's `event.player_id` is currently always the host's own id, even though the API shape allows for any player.
